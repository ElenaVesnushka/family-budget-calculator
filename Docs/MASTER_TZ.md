1.  Общая концепция проекта Название проекта Калькулятор семейного
    бюджета (рабочее название, может быть изменено позднее). Назначение
    проекта Проект предназначен для удобного и понятного ведения личного
    или семейного бюджета. Основная задача приложения --- помочь
    пользователю видеть реальную финансовую картину, понимать, куда
    поступают и расходуются деньги, контролировать выполнение бюджета,
    отслеживать изменение общего объёма средств и принимать более
    обоснованные финансовые решения. Приложение не является
    бухгалтерской системой и не заменяет банковские сервисы. Оно служит
    персональным инструментом финансового планирования и анализа.
    Основная идея Проект строится на принципе максимальной простоты
    использования без потери функциональности. Пользователь должен
    тратить минимум времени на ввод данных и получать максимум полезной
    информации. Каждая функция приложения должна отвечать хотя бы одному
    из трёх принципов: экономит время пользователя; помогает принимать
    финансовые решения; делает финансовую информацию более понятной.
    Если функция не соответствует ни одному из этих принципов, её
    необходимость должна быть дополнительно обоснована. Концепция учёта
    Проект разделяет два независимых направления учёта.

2.  Текущий бюджет Показывает движение денежных средств за выбранный
    период. Включает: доходы; расходы; лимиты; баланс периода;
    финансовую подушку; планируемые расходы; ожидаемые доходы;
    аналитику. Отвечает на вопрос: «Что происходит с бюджетом сейчас?»
    Оценка текущего финансового состояния выполняется на основании
    сравнения баланса периода с финансовой подушкой.

3.  Мои средства Показывает общий объём денежных средств пользователя
    независимо от текущего бюджета. Включает: банковские счета; карты;
    вклады; накопительные счета; наличные; другие источники хранения
    средств; назначение средств; историю ежемесячных снимков; динамику
    капитала. Отвечает на вопрос: «Как меняется общий объём моих
    средств?» Раздел «Мои средства» не используется для оценки текущего
    финансового состояния бюджета. Эти разделы
    независимы друг от друга, но при необходимости могут использовать
    общие справочные данные. Основные принципы проекта При разработке
    приложения соблюдаются следующие принципы. Простота освоения.
    Минимальное количество действий пользователя. Высокая наглядность
    данных. Максимальная достоверность финансовой информации. Все
    автоматические действия требуют подтверждения пользователя. Все
    расчёты должны быть прозрачными и воспроизводимыми. Интерфейс не
    должен перегружать пользователя информацией. Аналитика строится
    только на фактических данных. Все тексты приложения являются
    безгендерными. Пользователь полностью контролирует свои данные.
    Масштабируемость Архитектура проекта должна предусматривать
    дальнейшее развитие без необходимости полной переработки приложения.
    Планируется возможность добавления: облачной синхронизации;
    нескольких пользователей; мобильной версии; импорта банковских
    данных; дополнительных аналитических модулей; новых типов отчётов;
    интеграции с внешними сервисами. При этом каждая новая возможность
    должна добавляться как отдельный модуль и не нарушать работу уже
    существующего функционала. Ключевой принцип проекта Калькулятор
    должен быть не просто инструментом учёта доходов и расходов, а
    понятным, честным и удобным финансовым помощником, который помогает
    видеть реальную картину и принимать решения на основе собственных
    данных пользователя.

4.  Цели проекта Главная цель Создать современное, удобное и понятное
    приложение для ведения личного или семейного бюджета, которое
    помогает пользователю контролировать финансовое состояние,
    планировать расходы, анализировать изменения и принимать решения на
    основе собственных данных. Основные цели Финансовый учёт Обеспечить
    простой и быстрый учёт: доходов; расходов; планируемых расходов;
    ожидаемых доходов; накоплений; общего объёма средств.

Финансовый контроль Предоставить пользователю инструменты для контроля:
расходов по статьям; расходов по категориям; выполнения лимитов;
соблюдения финансовой подушки; изменения общего капитала.

Финансовое планирование Помочь пользователю заранее видеть: обязательные
будущие расходы; ожидаемые поступления; возможный дефицит бюджета;
влияние будущих операций на финансовое состояние.

Финансовая аналитика Автоматически анализировать данные пользователя и
отображать понятные наблюдения: динамику расходов; изменение доходов;
превышение лимитов; изменение общего объёма средств; повторяющиеся
финансовые тенденции. Аналитика должна строиться исключительно на данных
пользователя без предположений и субъективных оценок.

Простота использования Минимизировать время на ведение бюджета.
Приложение должно позволять выполнять большинство ежедневных операций за
минимальное количество действий.

Достоверность данных Все финансовые показатели должны отражать реальное
состояние бюджета. Приложение не должно автоматически создавать операции
без подтверждения пользователя. Все расчёты должны быть прозрачными и
проверяемыми.

Масштабируемость Проект должен иметь архитектуру, позволяющую постепенно
развивать функциональность без переработки уже реализованных модулей.

Критерии успешности проекта Проект считается успешным, если пользователь
может: быстро внести доход или расход; увидеть текущее финансовое
состояние; понять, сколько средств доступно; контролировать выполнение
лимитов; отслеживать изменение общего капитала; получать полезные
аналитические выводы; доверять каждому расчёту приложения.

3.  Пользователи Целевая аудитория Приложение предназначено для широкого
    круга пользователей независимо от пола, возраста и уровня финансовой
    подготовки. Оно должно быть одинаково удобным как для человека,
    который впервые начинает вести бюджет, так и для пользователя с
    многолетним опытом финансового учёта.

Основные категории пользователей Индивидуальный пользователь Ведёт
личный бюджет. Использует приложение для: учёта доходов; контроля
расходов; планирования бюджета; анализа финансового состояния; контроля
накоплений.

Семья Несколько членов семьи используют один общий бюджет. Пользователь
может учитывать: общие доходы; общие расходы; семейные накопления; общий
финансовый результат. В первой версии работа ведётся одним
пользователем. Полноценная многопользовательская работа предусмотрена
для будущих версий.

Пользователь с регулярным финансовым планированием Использует: лимиты;
плановые расходы; ожидаемые доходы; шаблоны операций; финансовую
подушку; анализ изменений.

Требования к интерфейсу Интерфейс должен быть понятен пользователю без
специальной подготовки. Каждое действие должно быть логичным и легко
прогнозируемым. Большинство ежедневных операций должно выполняться без
обращения к инструкции.

Универсальность Приложение не ориентировано на какую-либо профессию,
семейное положение или уровень дохода. Все настройки должны позволять
адаптировать приложение под индивидуальные потребности пользователя без
изменения основной логики работы.

Доступность При разработке интерфейса необходимо соблюдать следующие
требования: понятные названия элементов; единая терминология; отсутствие
профессионального жаргона без пояснений; читаемые размеры текста;
достаточный цветовой контраст; информативные сообщения об ошибках;
минимальное количество действий для выполнения операций.

Коммуникация с пользователем Все тексты приложения должны
соответствовать следующим принципам: безгендерные формулировки;
уважительный тон; отсутствие оценочных или осуждающих выражений;
рекомендации вместо категоричных указаний; понятные объяснения причин
предупреждений и уведомлений. Приложение должно выступать в роли
спокойного и надёжного помощника, помогая пользователю принимать
финансовые решения, не создавая ощущения контроля или давления.

4.  Основные принципы Общие принципы Разработка и развитие приложения
    должны основываться на следующих принципах. Простота Приложение
    должно быть понятным без длительного обучения. Даже сложные функции
    должны быть представлены простым и логичным интерфейсом.

Достоверность Все показатели должны отражать реальное финансовое
состояние пользователя. Приложение не должно выполнять предположений или
создавать финансовые операции автоматически. Любое изменение финансовых
данных требует подтверждения пользователя.

Прозрачность Любой расчёт должен быть понятен. Пользователь должен иметь
возможность определить, каким образом получен любой показатель
приложения.

Минимум действий Большинство ежедневных операций должно выполняться за
минимальное количество действий. Если существует возможность сократить
количество действий без потери понятности, следует использовать именно
такой вариант.

Гибкость Настройки приложения должны позволять адаптировать его под
различные финансовые привычки пользователя без изменения основной логики
работы.

Масштабируемость Каждый новый модуль должен легко подключаться к
существующей архитектуре без необходимости переработки уже
реализованного функционала.

Принципы работы с данными Все финансовые данные принадлежат
пользователю. Приложение не изменяет данные без подтверждения
пользователя. Все операции могут быть: добавлены; изменены; удалены;
скопированы. После любого изменения все расчёты автоматически
пересчитываются.

Принципы автоматизации Автоматизация должна помогать пользователю, а не
принимать решения вместо него. Основное правило проекта: Ни одна
финансовая операция не создаётся автоматически без подтверждения
пользователя. Это правило распространяется на: плановые расходы;
ожидаемые доходы; повторяющиеся операции; импорт данных; будущие
банковские интеграции.

Принципы аналитики Аналитика строится исключительно на фактических
данных пользователя. Приложение: не делает предположений; не оценивает
действия пользователя; не навязывает решения. Допускаются только
рекомендации, основанные на выявленных закономерностях.

Принципы интерфейса Интерфейс должен быть: современным; понятным;
визуально лёгким; последовательным; адаптивным. Каждый элемент
управления должен использоваться одинаково во всех разделах приложения.

Принципы коммуникации Все сообщения приложения должны быть:
безгендерными; уважительными; спокойными; понятными; доброжелательными.
Сообщения должны объяснять ситуацию и предлагать возможные действия без
критики пользователя.

Принципы развития проекта При разработке новых функций необходимо
соблюдать правило: Сначала сохраняется простота использования, затем
добавляется новый функционал. Каждая новая возможность должна отвечать
минимум одному из критериев: экономит время; повышает точность учёта;
улучшает понимание финансовой ситуации; упрощает работу пользователя.
Если новая функция не соответствует ни одному из этих критериев, её
внедрение требует дополнительного обоснования.

Главный принцип проекта Приложение должно помогать пользователю видеть
реальную финансовую картину, сохраняя полный контроль над данными и
решениями, а автоматизация должна оставаться помощником, а не заменой
самого пользователя.

Принцип финансовых показателей Каждый финансовый показатель должен
отвечать только на один вопрос пользователя. Если два показателя
отвечают на один и тот же вопрос, их назначение должно быть пересмотрено.

# 5. Архитектура

## Общая архитектура

Приложение строится по модульному принципу.

Каждый функциональный блок является самостоятельным модулем с
минимальной зависимостью от остальных частей проекта.

Такой подход позволяет:

-   постепенно расширять функциональность;
-   заменять отдельные модули без переработки всего проекта;
-   переносить проект с локального хранения данных на облачное;
-   создавать мобильную версию без изменения бизнес-логики.

------------------------------------------------------------------------

## Версии проекта

### Версия 1 (MVP)

Первая версия реализуется как локальное веб-приложение.

Основные характеристики:

-   один HTML-файл;
-   HTML + CSS + JavaScript;
-   хранение данных в localStorage;
-   работа без подключения к Интернету;
-   один пользователь.

------------------------------------------------------------------------

### Версия 2

Переход на полноценную структуру проекта.

Предусматривается разделение на отдельные файлы:

-   HTML;
-   CSS;
-   JavaScript;
-   изображения;
-   настройки.

------------------------------------------------------------------------

### Будущие версии

Архитектура должна позволять подключение:

-   базы данных;
-   облачного хранения;
-   нескольких пользователей;
-   мобильного приложения;
-   банковских интеграций;
-   импорта данных;
-   дополнительных аналитических модулей.

------------------------------------------------------------------------

## Основные модули

Архитектура приложения состоит из следующих независимых модулей.

### Главный экран

Отображает:

-   финансовое настроение;
-   баланс периода;
-   мои средства;
-   доходы периода;
-   расходы периода;
-   финансовую подушку;
-   последние операции;
-   основные уведомления.

Баланс периода, мои средства и финансовая подушка являются разными
показателями и не заменяют друг друга.

Баланс периода отражает состояние текущего бюджета. Мои средства
показывают объём активных денежных средств пользователя. Финансовая
подушка задаёт минимальный безопасный уровень.

------------------------------------------------------------------------

### Доходы

Отвечает за:

-   добавление доходов;
-   редактирование;
-   удаление;
-   ожидаемые доходы;
-   подтверждение поступлений.

------------------------------------------------------------------------

### Расходы

Отвечает за:

-   добавление расходов;
-   категории;
-   статьи;
-   повторяющиеся расходы;
-   шаблоны;
-   подтверждение плановых расходов.

------------------------------------------------------------------------

### Лимиты

Выполняет:

-   хранение лимитов;
-   контроль выполнения;
-   анализ перерасхода;
-   отображение остатка лимита.

------------------------------------------------------------------------

### Финансовая подушка

Отвечает за:

-   хранение настроек;
-   расчёт целевого размера подушки;
-   предупреждения;
-   сравнение с балансом периода при оценке финансового состояния.

------------------------------------------------------------------------

### Мои средства

Отдельный независимый модуль.

Содержит:

-   счета;
-   карты;
-   вклады;
-   наличные;
-   историю ежемесячных снимков;
-   сравнение месяцев;
-   капитализацию вкладов.

------------------------------------------------------------------------

### Аналитика

Формирует:

-   подробный анализ за выбранный период;
-   рекомендации;
-   сравнение периодов;
-   изменение капитала;
-   динамику расходов.

Финансовые наблюдения на главном экране не являются полноценной
аналитикой и описаны отдельно.

------------------------------------------------------------------------

### Настройки

Хранит пользовательские параметры:

-   дата начала финансового периода;
-   финансовая подушка;
-   темы оформления;
-   дата ежемесячного снимка;
-   справочники;
-   другие пользовательские настройки.

------------------------------------------------------------------------

## Независимость модулей

Каждый модуль должен работать самостоятельно.

Изменение одного модуля не должно требовать переработки остальных.

Обмен данными между модулями осуществляется только через общие структуры
данных.

------------------------------------------------------------------------

## Бизнес-логика

Бизнес-логика полностью отделяется от интерфейса.

Интерфейс отвечает только за отображение данных и взаимодействие с
пользователем.

Все вычисления выполняются отдельным программным слоем.

Это позволит в будущем использовать одну и ту же логику:

-   в веб-версии;
-   в мобильном приложении;
-   в облачной версии.

------------------------------------------------------------------------

## Хранение данных

В первой версии используется localStorage.

Архитектура должна предусматривать возможность перехода на:

-   SQLite;
-   PostgreSQL;
-   Firebase;
-   Supabase;
-   другие системы хранения данных.

Без изменения пользовательской логики приложения.

------------------------------------------------------------------------

## Принцип расширения

Каждая новая функция должна подключаться как отдельный модуль.

Запрещается изменять существующую архитектуру, если новую возможность
можно реализовать через расширение существующих модулей.

------------------------------------------------------------------------

## Архитектурный принцип проекта

> **Архитектура приложения должна обеспечивать простоту развития
> проекта, минимальную связанность модулей, независимость бизнес-логики
> от интерфейса и возможность масштабирования без полной переработки
> системы.** \# 6. Интерфейс

## Общая концепция

Интерфейс приложения должен быть современным, лёгким, интуитивно
понятным и визуально спокойным.

Основная задача интерфейса --- предоставить пользователю всю необходимую
информацию без перегрузки экрана.

При разработке интерфейса приоритет отдаётся удобству использования, а
не количеству отображаемых элементов.

------------------------------------------------------------------------

## Основные требования

Интерфейс должен быть:

-   современным;
-   минималистичным;
-   адаптивным;
-   последовательным;
-   визуально лёгким;
-   понятным без инструкции.

------------------------------------------------------------------------

## Основной стиль

При разработке используются следующие принципы:

-   светлая цветовая гамма по умолчанию;
-   мягкие оттенки без агрессивных цветов;
-   хорошие контрастность и читаемость;
-   скруглённые элементы управления;
-   достаточные внутренние отступы;
-   крупные зоны нажатия.

------------------------------------------------------------------------

## Темы оформления

Приложение должно поддерживать несколько тем оформления.

В первой версии:

-   Светлая;
-   Тёмная;
-   Японская (спокойные природные оттенки).

В дальнейшем пользователь сможет создавать собственные темы.

------------------------------------------------------------------------

## Навигация

Все основные разделы приложения должны быть доступны не более чем за два
действия пользователя.

Переход между разделами должен быть быстрым и логичным.

------------------------------------------------------------------------

## Главный экран

Главный экран отображает только наиболее важную информацию.

Обязательные элементы:

-   Финансовое настроение;
-   Баланс периода;
-   Мои средства;
-   Доходы периода;
-   Расходы периода;
-   Финансовая подушка;
-   Последние операции;
-   Основные уведомления;
-   Быстрые действия.

Смысл показателей:

-   **Баланс периода** --- состояние текущего бюджета;
-   **Мои средства** --- объём активных денежных средств пользователя;
-   **Финансовая подушка** --- минимальный безопасный уровень.

Баланс периода, мои средства и финансовая подушка являются разными
показателями и не заменяют друг друга.

------------------------------------------------------------------------

## Форма добавления операций

Форма автоматически изменяется в зависимости от выбранного типа
операции.

### Доход

Отображаются:

-   Вид дохода;
-   Название траты/дохода;
-   Дата;
-   Сумма;
-   Комментарий.

Скрываются:

-   Категория;
-   Статья;
-   Настройки повторения расходов.

------------------------------------------------------------------------

### Расход

Отображаются:

-   Категория;
-   Статья;
-   Название траты/дохода;
-   Дата;
-   Сумма;
-   Комментарий;
-   Настройки повтора (при необходимости).

Скрываются:

-   Вид дохода.

------------------------------------------------------------------------

## Отображение данных

Числовые показатели должны отображаться крупнее остальных элементов.

Главные показатели выделяются визуально.

Второстепенная информация отображается менее контрастно.

------------------------------------------------------------------------

## Цветовое кодирование

Использование цвета должно дополнять информацию, но не быть единственным
способом передачи смысла.

Рекомендуемые цвета:

-   доходы --- зелёный;
-   расходы --- красный;
-   предупреждения --- жёлтый;
-   информационные сообщения --- синий;
-   нейтральные элементы --- серый.

------------------------------------------------------------------------

## Финансовое настроение

Финансовое настроение --- самостоятельный постоянный информационный блок
главного экрана.

Оно:

-   является отображением текущего финансового состояния;
-   основано только на сравнении баланса периода и финансовой подушки;
-   не является отдельным финансовым расчётом;
-   не является уведомлением;
-   не является аналитикой;
-   не заменяет баланс периода и другие финансовые показатели;
-   описывает текущее состояние только на основании фактических данных.

Для определения состояния используются:

-   баланс периода;
-   финансовая подушка.

Возможные состояния на главном экране:

-   Стабильное;
-   Допустимое;
-   Требует внимания;
-   Критическое.

Логика сравнения баланса периода и финансовой подушки:

-   **Стабильное** --- баланс периода выше финансовой подушки.
    Пользователь покрывает текущие расходы и сохраняет безопасный
    уровень;
-   **Допустимое** --- баланс периода равен финансовой подушке.
    Пользователь находится на границе безопасного уровня;
-   **Требует внимания** --- баланс периода положительный, но ниже
    финансовой подушки. Текущая ситуация положительная, но уровень
    безопасности не достигнут;
-   **Критическое** --- баланс периода отрицательный. Доходы периода не
    покрывают расходы периода.

Для отображения текста используются группы пользовательских и системных
фраз:

-   положительное;
-   нейтральное;
-   предупреждение;
-   критическое.

Одному состоянию может соответствовать несколько групп фраз. Например,
для состояния «Стабильное» допускается использование фраз из групп
«положительное» и «нейтральное».

Пересчёт финансового настроения выполняется:

-   при открытии главного экрана;
-   после изменения доходов;
-   после изменения расходов;
-   после изменения финансовой подушки.

Финансовое настроение должно быть лаконичным, понятным и
доброжелательным.

Тексты не должны содержать гендерных обращений.

------------------------------------------------------------------------

## Уведомления

Все уведомления должны:

-   объяснять причину;
-   предлагать возможное действие;
-   не обвинять пользователя;
-   не использовать тревожные формулировки без необходимости.

------------------------------------------------------------------------

## Сообщения

Все сообщения приложения должны быть:

-   безгендерными;
-   понятными;
-   краткими;
-   дружелюбными;
-   уважительными.

------------------------------------------------------------------------

## Работа с длинными списками

При увеличении количества операций интерфейс должен сохранять удобство
работы.

Предусматриваются:

-   поиск;
-   фильтрация;
-   сортировка;
-   группировка.

------------------------------------------------------------------------

## Адаптивность

Интерфейс должен корректно работать:

-   на компьютерах;
-   на планшетах;
-   на смартфонах.

Основной сценарий первой версии --- использование на компьютере.

------------------------------------------------------------------------

## Доступность

Интерфейс должен учитывать требования доступности:

-   достаточный размер текста;
-   высокий контраст;
-   понятные подписи элементов;
-   логичный порядок перехода между элементами;
-   возможность управления только с клавиатуры.

------------------------------------------------------------------------

## Принцип проектирования интерфейса

При выборе между красивым и понятным интерфейсом приоритет всегда
отдаётся понятному.

Каждый элемент интерфейса должен отвечать на один из вопросов:

-   помогает быстрее выполнить действие;
-   помогает лучше понять финансовую ситуацию;
-   уменьшает вероятность ошибки пользователя.

Если элемент не выполняет ни одну из этих функций, его необходимость
должна быть дополнительно обоснована. истемы.\*\* \# 7. Доходы

## Назначение

Раздел «Доходы» предназначен для учёта всех денежных поступлений,
влияющих на текущий бюджет.

Доходы используются при расчёте:

-   доходов периода;
-   баланса периода;
-   финансового результата выбранного периода;
-   финансового настроения;
-   аналитики.

------------------------------------------------------------------------

## Виды доходов

В приложении используются три вида доходов:

-   Постоянный;
-   Разовый;
-   Капитализация вклада.

------------------------------------------------------------------------

### Постоянный доход

Используется для регулярных поступлений.

Например:

-   заработная плата;
-   пенсия;
-   алименты;
-   арендные платежи;
-   другие регулярные поступления.

------------------------------------------------------------------------

### Разовый доход

Используется для нерегулярных поступлений.

Например:

-   подарок;
-   премия;
-   продажа имущества;
-   возврат долга;
-   перевод между своими счетами;
-   заёмные средства.

------------------------------------------------------------------------

### Капитализация вклада

Используется только для учёта увеличения суммы вклада.

Такой доход:

-   не увеличивает текущий бюджет;
-   не влияет на баланс периода;
-   учитывается только во вкладке «Мои средства».

Если проценты были перечислены на доступный счёт, приложение предлагает:

> **Проценты поступили на доступный счёт. Добавить их в доходы текущего
> периода?**

При подтверждении создаётся обычный разовый доход.

------------------------------------------------------------------------

## Форма добавления дохода

На вкладке «Доходы» отображаются только следующие поля:

-   Вид дохода;
-   Название траты/дохода;
-   Дата;
-   Сумма;
-   Комментарий.

Не отображаются:

-   Категория расходов;
-   Статья расходов;
-   Настройки повторяющихся расходов.

------------------------------------------------------------------------

## Обязательные поля

При добавлении дохода обязательны:

-   дата;
-   вид дохода;
-   сумма.

Необязательные:

-   название;
-   комментарий.

------------------------------------------------------------------------

## Работа с датами

Доход можно:

-   добавить текущей датой;
-   внести задним числом;
-   внести заранее как ожидаемый доход.

Ограничения:

-   не ранее 30 дней назад;
-   не позднее 60 дней вперёд.

------------------------------------------------------------------------

## Ожидаемые доходы

Для регулярных поступлений используется механизм «Ожидаемые доходы».

Настраиваются:

-   планируемая дата;
-   периодичность;
-   предполагаемая сумма;
-   название;
-   комментарий.

До подтверждения ожидаемый доход:

-   отображается отдельно;
-   не учитывается в расчётах;
-   не влияет на текущий баланс.

После наступления даты приложение показывает уведомление:

> **Ожидалось поступление «Название дохода». Проверьте сумму и
> подтвердите получение.**

Пользователь может:

-   подтвердить поступление;
-   изменить сумму;
-   отложить;
-   пропустить.

Только после подтверждения доход включается в расчёты.

------------------------------------------------------------------------

## Редактирование

Каждый доход можно:

-   изменить;
-   удалить;
-   скопировать.

После любого изменения автоматически пересчитываются:

-   доходы периода;
-   баланс периода;
-   финансовое настроение;
-   аналитика;
-   отчёты.

------------------------------------------------------------------------

## Импорт данных

Первая версия использует только ручной ввод.

Будущие версии предусматривают импорт:

-   CSV;
-   Excel;
-   банковских выписок.

Любой импорт требует обязательного подтверждения пользователя перед
добавлением операций.

------------------------------------------------------------------------

## Принципы раздела

Раздел «Доходы» должен обеспечивать:

-   быстрый ввод информации;
-   достоверность данных;
-   отсутствие двойного учёта;
-   прозрачность расчётов;
-   обязательное подтверждение любых автоматически предложенных
    операций.

# 8. Расходы

## Назначение

Раздел «Расходы» предназначен для учёта всех денежных затрат, влияющих
на текущий бюджет.

На основании расходов рассчитываются:

-   расходы периода;
-   баланс периода;
-   соблюдение лимитов;
-   финансовое настроение;
-   финансовая аналитика.

------------------------------------------------------------------------

## Структура расходов

Каждый расход относится одновременно:

-   к категории;
-   к статье.

Категория определяет общий тип расхода.

Статья позволяет объединять одинаковые расходы независимо от категории.

------------------------------------------------------------------------

## Категории расходов

В первой версии используются две категории:

-   Обязательные;
-   Для души.

Пользователь может самостоятельно добавлять новые категории в будущих
версиях приложения.

------------------------------------------------------------------------

## Статьи расходов

По умолчанию доступны следующие статьи:

-   Питание;
-   Животные;
-   Авто;
-   Дом;
-   Кредиты;
-   Обучение;
-   Здоровье;
-   Личные.

Пользователь может создавать собственные статьи расходов.

Все добавленные статьи сохраняются и доступны при последующем
использовании.

------------------------------------------------------------------------

## Форма добавления расхода

При создании расхода отображаются следующие поля:

-   Категория;
-   Статья;
-   Название траты/дохода;
-   Дата;
-   Сумма;
-   Комментарий.

При необходимости дополнительно отображаются настройки повторения.

------------------------------------------------------------------------

## Обязательные поля

При добавлении расхода обязательны:

-   дата;
-   категория;
-   статья;
-   сумма.

Необязательные:

-   название;
-   комментарий.

------------------------------------------------------------------------

## Работа с датами

Расход можно:

-   добавить текущей датой;
-   внести задним числом;
-   запланировать заранее.

Ограничения:

-   не ранее 30 дней назад;
-   не позднее 60 дней вперёд.

------------------------------------------------------------------------

## Плановые расходы

Пользователь может создавать повторяющиеся расходы.

Поддерживаются варианты повторения:

-   ежедневно;
-   еженедельно;
-   ежемесячно;
-   каждые N дней.

После наступления плановой даты приложение предлагает подтвердить
выполнение расхода.

Пользователь может:

-   подтвердить расход;
-   изменить сумму;
-   перенести дату;
-   пропустить операцию.

До подтверждения расход не учитывается в расчётах.

------------------------------------------------------------------------

## Шаблоны расходов

После сохранения расхода приложение может предложить создать шаблон.

Шаблон сохраняет:

-   категорию;
-   статью;
-   название;
-   сумму;
-   комментарий;
-   параметры повторения (при наличии).

Использование шаблона не создаёт расход автоматически.

Перед сохранением пользователь может изменить любые значения.

------------------------------------------------------------------------

## Редактирование

Каждый расход можно:

-   изменить;
-   удалить;
-   скопировать.

После любого изменения автоматически пересчитываются:

-   расходы периода;
-   баланс периода;
-   лимиты;
-   финансовое настроение;
-   аналитика;
-   отчёты.

------------------------------------------------------------------------

## Связь с лимитами

Каждый расход автоматически учитывается:

-   в лимите своей категории;
-   в лимите своей статьи.

Если установлен лимит, приложение отображает:

-   сумму лимита;
-   уже израсходованную сумму;
-   оставшийся лимит;
-   перерасход (при наличии).

------------------------------------------------------------------------

## Импорт данных

Первая версия предусматривает только ручной ввод расходов.

В будущих версиях планируется поддержка импорта:

-   CSV;
-   Excel;
-   банковских выписок.

Импортированные операции добавляются только после подтверждения
пользователя.

------------------------------------------------------------------------

## Принципы раздела

Раздел «Расходы» должен обеспечивать:

-   быстрый ввод операций;
-   удобную классификацию расходов;
-   прозрачный контроль бюджета;
-   корректную работу с лимитами;
-   обязательное подтверждение автоматически предложенных операций;
-   отсутствие автоматического создания расходов без участия
    пользователя. \# 9. Лимиты

## Назначение

Раздел «Лимиты» предназначен для планирования расходов и контроля
соблюдения установленного бюджета.

Лимиты помогают заранее определить допустимые расходы и своевременно
замечать отклонения.

------------------------------------------------------------------------

## Виды лимитов

В приложении используются два вида лимитов:

-   лимит по категории;
-   лимит по статье.

Оба вида работают независимо друг от друга.

------------------------------------------------------------------------

## Лимит по категории

Лимит по категории устанавливается для всей категории расходов.

Например, лимит категории «Обязательные» учитывает сумму всех расходов,
относящихся к этой категории.

Приложение автоматически рассчитывает:

-   установленный лимит;
-   сумму уже произведённых расходов;
-   оставшийся лимит;
-   величину перерасхода.

------------------------------------------------------------------------

## Лимит по статье

Лимит по статье распространяется на все расходы выбранной статьи
независимо от категории.

Например, если статья «Питание» используется в разных категориях, при
расчёте лимита учитываются все расходы по этой статье.

Приложение автоматически рассчитывает:

-   установленный лимит;
-   сумму расходов по статье;
-   оставшийся лимит;
-   величину перерасхода.

------------------------------------------------------------------------

## Независимость лимитов

Лимиты по категории и по статье не заменяют друг друга.

Один и тот же расход одновременно учитывается:

-   в лимите своей категории;
-   в лимите своей статьи.

------------------------------------------------------------------------

## Период действия

Лимиты устанавливаются для выбранного финансового периода.

По окончании периода они не переносятся автоматически.

При начале нового периода пользователь самостоятельно определяет
значения лимитов.

------------------------------------------------------------------------

## Отображение информации

Для каждого лимита отображаются:

-   название;
-   установленная сумма;
-   сумма фактических расходов;
-   остаток;
-   процент использования.

Информация обновляется автоматически после каждой операции.

------------------------------------------------------------------------

## Цветовая индикация

Для наглядности используется цветовое обозначение состояния лимита.

Рекомендуемые состояния:

-   в пределах лимита --- нейтральное отображение;
-   приближение к лимиту --- предупреждение;
-   превышение лимита --- выделение красным цветом.

Цвет является дополнительным способом отображения информации и не должен
быть единственным индикатором состояния.

------------------------------------------------------------------------

## Перерасход

Если расходы превышают установленный лимит, приложение:

-   показывает сумму перерасхода;
-   выделяет соответствующий лимит;
-   учитывает превышение в аналитике.

Превышение лимита не запрещает дальнейшее добавление расходов.

Лимиты являются инструментом контроля, а не ограничением работы
приложения.

------------------------------------------------------------------------

## Сравнение с доходами

При наличии постоянного дохода приложение может отображать:

-   долю лимита от среднемесячного дохода;
-   процент фактических расходов от дохода.

Эти показатели носят исключительно информационный характер.

------------------------------------------------------------------------

## Изменение лимитов

Пользователь может в любой момент:

-   установить лимит;
-   изменить его значение;
-   удалить лимит.

После изменения автоматически пересчитываются:

-   остатки;
-   проценты использования;
-   аналитика;
-   уведомления.

------------------------------------------------------------------------

## Использование в аналитике

Данные о лимитах используются для формирования финансовых наблюдений.

Например:

-   регулярное превышение определённого лимита;
-   значительное изменение структуры расходов;
-   высокий процент использования лимита до окончания периода.

Аналитика носит рекомендательный характер и не содержит оценочных
суждений.

------------------------------------------------------------------------

## Принципы раздела

Система лимитов должна:

-   помогать планировать расходы;
-   быть понятной без дополнительного обучения;
-   автоматически пересчитываться после каждой операции;
-   не ограничивать пользователя в добавлении расходов;
-   предоставлять объективную информацию о состоянии бюджета. \# 10.
    Плановые расходы

## Назначение

Раздел «Плановые расходы» предназначен для планирования будущих расходов
и напоминания о них.

Плановые расходы помогают не забывать о регулярных платежах, но не
заменяют фактически совершённые операции.

------------------------------------------------------------------------

## Основной принцип

Создание планового расхода не означает автоматическое создание расходной
операции.

После наступления даты приложение предлагает пользователю подтвердить
расход.

До подтверждения расход:

-   не учитывается в бюджете;
-   не уменьшает баланс периода;
-   не влияет на отчёты;
-   не учитывается при расчёте лимитов.

------------------------------------------------------------------------

## Настройка планового расхода

Для каждого планового расхода задаются:

-   название;
-   категория;
-   статья;
-   предполагаемая сумма;
-   дата первого выполнения;
-   периодичность;
-   комментарий (необязательно).

------------------------------------------------------------------------

## Варианты повторения

Поддерживаются следующие варианты:

-   ежедневно;
-   еженедельно;
-   ежемесячно;
-   каждые N дней.

Архитектура приложения должна позволять добавление новых вариантов
повторения без изменения существующей логики.

------------------------------------------------------------------------

## Наступление даты

После наступления запланированной даты приложение отображает
уведомление.

Например:

> **Запланирован расход «Название». Подтвердите выполнение операции.**

Пока пользователь не примет решение, расход остаётся в статусе ожидания.

------------------------------------------------------------------------

## Действия пользователя

Для каждого планового расхода доступны следующие действия:

-   подтвердить;
-   изменить сумму;
-   перенести дату;
-   пропустить.

------------------------------------------------------------------------

### Подтвердить

После подтверждения создаётся обычная расходная операция.

Именно с этого момента расход:

-   учитывается в бюджете;
-   участвует в расчёте лимитов;
-   влияет на баланс периода и финансовое настроение;
-   включается в отчёты и аналитику.

------------------------------------------------------------------------

### Изменить сумму

Перед подтверждением пользователь может изменить сумму расхода.

После подтверждения создаётся операция уже с новой суммой.

------------------------------------------------------------------------

### Перенести дату

Пользователь может перенести выполнение расхода на другую дату.

При этом расход остаётся плановым и не учитывается в расчётах.

------------------------------------------------------------------------

### Пропустить

Если расход не состоялся, пользователь может пропустить его.

В этом случае операция не создаётся.

Следующее повторение рассчитывается согласно установленной
периодичности.

------------------------------------------------------------------------

## Редактирование

Плановый расход можно:

-   изменить;
-   временно отключить;
-   удалить;
-   скопировать.

Изменения применяются только к будущим повторениям.

------------------------------------------------------------------------

## Связь с шаблонами

Плановый расход может быть создан:

-   вручную;
-   на основе шаблона;
-   при сохранении обычного расхода.

Во всех случаях применяется единая логика подтверждения.

------------------------------------------------------------------------

## Уведомления

После наступления даты приложение напоминает о необходимости проверить
выполнение расхода.

Уведомление должно:

-   быть кратким;
-   объяснять ожидаемое действие;
-   не создавать ощущение срочности без необходимости.

------------------------------------------------------------------------

## Принципы раздела

Система плановых расходов должна обеспечивать:

-   удобное планирование регулярных платежей;
-   отсутствие автоматического создания расходов;
-   обязательное подтверждение пользователем;
-   возможность изменить параметры непосредственно перед созданием
    операции;
-   прозрачность и предсказуемость работы. \# 11. Ожидаемые доходы

## Назначение

Раздел «Ожидаемые доходы» предназначен для планирования будущих денежных
поступлений и напоминания об их получении.

Ожидаемые доходы помогают учитывать запланированные поступления, не
влияя на текущий бюджет до момента их фактического получения.

------------------------------------------------------------------------

## Основной принцип

Создание ожидаемого дохода не означает автоматическое создание доходной
операции.

После наступления запланированной даты приложение предлагает
пользователю подтвердить получение денежных средств.

До подтверждения ожидаемый доход:

-   не учитывается в доходах периода;
-   не влияет на баланс периода;
-   не участвует в расчётах бюджета;
-   не включается в отчёты и аналитику.

------------------------------------------------------------------------

## Настройка ожидаемого дохода

Для каждого ожидаемого дохода задаются:

-   вид дохода;
-   название;
-   предполагаемая сумма;
-   дата поступления;
-   периодичность;
-   комментарий (необязательно).

------------------------------------------------------------------------

## Варианты повторения

Поддерживаются следующие варианты:

-   ежедневно;
-   еженедельно;
-   ежемесячно;
-   каждые N дней.

Архитектура приложения должна позволять добавление новых вариантов
повторения без изменения существующей логики.

------------------------------------------------------------------------

## Наступление даты

После наступления запланированной даты приложение отображает
уведомление.

Например:

> **Ожидалось поступление «Название». Проверьте сумму и подтвердите
> получение.**

Пока пользователь не примет решение, ожидаемый доход остаётся в статусе
ожидания.

------------------------------------------------------------------------

## Действия пользователя

Для каждого ожидаемого дохода доступны следующие действия:

-   подтвердить;
-   изменить сумму;
-   перенести дату;
-   пропустить.

------------------------------------------------------------------------

### Подтвердить

После подтверждения создаётся обычная доходная операция.

Именно с этого момента доход:

-   учитывается в доходах периода;
-   влияет на баланс периода и финансовое настроение;

-   участвует в аналитике.

------------------------------------------------------------------------

### Изменить сумму

Перед подтверждением пользователь может изменить сумму поступления.

После подтверждения создаётся доходная операция уже с новой суммой.

------------------------------------------------------------------------

### Перенести дату

Пользователь может изменить ожидаемую дату поступления.

Доход остаётся в статусе ожидания и не участвует в расчётах.

------------------------------------------------------------------------

### Пропустить

Если поступление не произошло, пользователь может пропустить ожидаемый
доход.

В этом случае доходная операция не создаётся.

Следующее повторение рассчитывается в соответствии с установленной
периодичностью.

------------------------------------------------------------------------

-   изменить;
-   временно отключить;
-   удалить;

Изменения применяются только к будущим повторениям.

-   не создавать ощущение срочности без необходимости.

------------------------------------------------------------------------

## Принципы раздела

    операции;

# 12. Шаблоны

## Назначение

Раздел «Шаблоны» предназначен для ускорения ввода регулярно
повторяющихся операций.

Шаблон содержит заранее подготовленный набор данных, который
пользователь может использовать при создании новой операции.

------------------------------------------------------------------------

## Основной принцип

Шаблон не является финансовой операцией.

Создание, изменение или удаление шаблона не влияет:

-   на бюджет;
-   на доходы;
-   на расходы;
-   на баланс периода;
-   на лимиты;
-   на отчёты;
-   на аналитику.

Шаблон используется только как заготовка для создания новой операции.

------------------------------------------------------------------------

## Создание шаблона

Шаблон можно создать:

-   вручную;
-   после сохранения дохода;
-   после сохранения расхода.

После добавления операции приложение может предложить:

> **Создать шаблон для этой операции?**

Создание шаблона выполняется только после подтверждения пользователя.

------------------------------------------------------------------------

## Типы шаблонов

Поддерживаются два типа шаблонов:

-   шаблон дохода;
-   шаблон расхода.

------------------------------------------------------------------------

## Шаблон дохода

Шаблон дохода может содержать:

-   вид дохода;
-   название;
-   сумму;
-   комментарий;
-   параметры ожидаемого дохода (при необходимости).

------------------------------------------------------------------------

## Шаблон расхода

Шаблон расхода может содержать:

-   категорию;
-   статью;
-   название;
-   сумму;
-   комментарий;
-   параметры планового расхода (при необходимости).

------------------------------------------------------------------------

## Использование шаблона

При выборе шаблона создаётся форма новой операции, заполненная данными
шаблона.

До сохранения пользователь может изменить любое поле.

Финансовая операция создаётся только после подтверждения сохранения.

------------------------------------------------------------------------

## Редактирование шаблонов

Каждый шаблон можно:

-   изменить;
-   удалить;
-   скопировать;
-   временно отключить.

Отключённые шаблоны сохраняются, но не отображаются в списке доступных
для выбора.

------------------------------------------------------------------------

## Хранение шаблонов

Все шаблоны сохраняются отдельно от финансовых операций.

Удаление операции не приводит к удалению связанного шаблона.

Удаление шаблона не влияет на ранее созданные операции.

------------------------------------------------------------------------

## Поиск и сортировка

При большом количестве шаблонов должны поддерживаться:

-   поиск по названию;
-   сортировка по типу;
-   сортировка по алфавиту;
-   сортировка по дате последнего использования.

------------------------------------------------------------------------

## Будущие возможности

Архитектура должна предусматривать возможность добавления:

-   избранных шаблонов;
-   групп шаблонов;
-   цветовых меток;
-   пользовательских иконок;
-   импорта и экспорта шаблонов.

------------------------------------------------------------------------

## Принципы раздела

Система шаблонов должна обеспечивать:

-   быстрое создание новых операций;
-   отсутствие автоматического создания финансовых операций;
-   возможность изменять данные перед сохранением;
-   независимость шаблонов от истории операций;
-   простоту управления большим количеством шаблонов. \# 13. Финансовая
    подушка

## Финансовые показатели и формулы

Ниже приведены определения и формулы основных финансовых показателей
приложения. Каждый показатель отвечает на отдельный вопрос пользователя
и не дублирует другие показатели.

### Баланс периода

Баланс периода показывает результат подтверждённых операций текущего
финансового периода и является основным показателем оценки текущего
финансового состояния.

> **Баланс периода = Доходы подтверждённых операций выбранного периода −
> Расходы подтверждённых операций выбранного периода**

Баланс периода не зависит от раздела «Мои средства» и не включает
финансовую подушку в свой расчёт.

Подтверждённые доходы и расходы --- это фактические операции,
сохранённые в разделах «Доходы» и «Расходы». Плановые расходы и
ожидаемые доходы до подтверждения в расчёт не включаются.

### Текущие средства

Текущие средства --- сумма активных средств с назначением «Текущие
средства».

> **Текущие средства = сумма всех активных средств с назначением
> «Текущие средства»**

Текущие средства предназначены для повседневного финансового оборота.

### Финансовые запасы

Финансовые запасы --- сумма активных средств с назначением «Финансовые
запасы».

> **Финансовые запасы = сумма всех активных средств с назначением
> «Финансовые запасы»**

Финансовые запасы не участвуют в постоянном повседневном обороте.

### Общие средства

> **Общие средства = Текущие средства + Финансовые запасы**

Общие средства рассчитываются на основании данных раздела «Мои средства»
и показывают объём активов пользователя. Они не используются для оценки
текущего финансового состояния бюджета.

### Финансовая подушка

Финансовая подушка --- минимальный безопасный уровень, установленный
пользователем.

Финансовая подушка:

-   не входит в расчёт баланса периода;
-   используется как порог сравнения с балансом периода;
-   применяется при определении финансового настроения.

------------------------------------------------------------------------

## Назначение

Раздел предназначен для контроля финансовой устойчивости пользователя.

Приложение помогает задать минимальный безопасный уровень денежных
средств, своевременно предупреждает о снижении баланса периода
относительно этого уровня и отображает понятную интерпретацию текущего
финансового состояния.

------------------------------------------------------------------------

## Основные понятия

### Финансовая подушка

Финансовая подушка --- это минимальный безопасный уровень средств,
который пользователь считает необходимым сохранять.

Размер финансовой подушки задаётся:

-   фиксированной суммой;
-   процентом от дохода.

Финансовая подушка не является расходуемой суммой текущего бюджета и не
вычитается из баланса периода или из средств пользователя.

### Баланс периода

Баланс периода --- основной показатель оценки текущего финансового
состояния.

Он сравнивается с финансовой подушкой для определения финансового
настроения.

------------------------------------------------------------------------

## Способы задания финансовой подушки

Пользователь может выбрать один из вариантов расчёта.

### Фиксированная сумма

Пользователь самостоятельно указывает необходимую сумму.

Например:

-   100 000 ₽;
-   300 000 ₽;
-   1 000 000 ₽.

------------------------------------------------------------------------

### Процент от дохода

Размер подушки рассчитывается автоматически как процент от доходов
выбранного периода.

Процент задаётся пользователем.

Финансовая подушка не является суммой, которую нужно вычесть из средств.
Она используется как граница безопасности.

------------------------------------------------------------------------

## Сравнение баланса периода и финансовой подушки

Текущее финансовое состояние определяется сравнением баланса периода с
финансовой подушкой.

| Состояние | Условие | Смысл |
| --- | --- | --- |
| Стабильное | Баланс периода выше финансовой подушки | Пользователь покрывает текущие расходы и сохраняет безопасный уровень |
| Допустимое | Баланс периода равен финансовой подушке | Пользователь находится на границе безопасного уровня |
| Требует внимания | Баланс периода положительный, но ниже финансовой подушки | Текущая ситуация положительная, но уровень безопасности не достигнут |
| Критическое | Баланс периода отрицательный | Доходы периода не покрывают расходы периода |

Финансовая подушка при этом сравнении используется только как порог
оценки и не изменяет значение баланса периода.

------------------------------------------------------------------------

## Отображение на главном экране

На главном экране независимо отображаются:

-   финансовое настроение;
-   баланс периода;
-   мои средства;
-   доходы периода;
-   расходы периода;
-   финансовая подушка;
-   последние операции;
-   предупреждения (при необходимости).

При изменении доходов и расходов пересчитываются баланс периода и
финансовое настроение.

При изменении финансовой подушки пересчитываются связанные показатели
оценки состояния и финансовое настроение.

------------------------------------------------------------------------

## Предупреждения

Если баланс периода становится меньше финансовой подушки или
отрицательным, приложение может отобразить предупреждение.

Сообщения должны быть:

-   спокойными;
-   информативными;
-   без обвинительных формулировок;
-   без гендерных обращений.

Например:

> **Баланс периода ниже установленного безопасного уровня. Проверьте
> расходы и размер финансовой подушки.**

------------------------------------------------------------------------

## Отрицательный баланс периода

Если баланс периода становится отрицательным, приложение информирует
пользователя.

Например:

> **Текущие доходы не покрывают текущие расходы. Возможно, стоит
> пересмотреть расходы или ожидаемые поступления.**

Приложение не запрещает дальнейшую работу и не ограничивает создание
новых операций.

------------------------------------------------------------------------

## Изменение финансовой подушки

Пользователь может в любой момент:

-   изменить способ расчёта;
-   изменить размер подушки;
-   временно отключить использование финансовой подушки.

После изменения автоматически пересчитываются:

-   финансовое настроение;
-   предупреждения;
-   аналитика.

Если финансовая подушка временно отключена, оценка финансового
настроения по сравнению с подушкой не выполняется до её повторного
включения. В этом случае приложение может отображать нейтральное
состояние или опираться только на знак баланса периода.

------------------------------------------------------------------------

## Использование в аналитике

Данные о финансовой подушке используются только для формирования
информационных наблюдений.

Например:

-   как часто баланс периода оказывается ниже финансовой подушки;
-   насколько стабильно сохраняется финансовая подушка;
-   как изменение расходов влияет на баланс периода и финансовое
    настроение.

Аналитика носит исключительно рекомендательный характер.

------------------------------------------------------------------------

## Будущие возможности

Архитектура должна предусматривать возможность добавления:

-   нескольких финансовых целей;
-   отдельных резервных фондов;
-   накопительных счетов;
-   автоматического распределения свободных средств между целями;
-   прогнозирования срока достижения финансовых целей.

------------------------------------------------------------------------

## Принципы раздела

Система финансовой подушки должна:

-   помогать сохранять финансовую устойчивость;
-   использовать подушку как минимальный безопасный уровень;
-   сравнивать баланс периода с финансовой подушкой при оценке
    состояния;
-   предоставлять пользователю объективную информацию;
-   не ограничивать действия пользователя;
-   мотивировать к осознанному управлению личными финансами без
    оценочных суждений. \# 14. Вкладка «Мои средства»

## Назначение

Вкладка «Мои средства» предназначена для учёта всех денежных активов
пользователя независимо от их использования в текущем бюджете.

Раздел позволяет видеть объём активов пользователя, отслеживать
изменение капитала и анализировать рост или снижение собственных
средств.

Мои средства не используются для оценки текущего финансового состояния
бюджета. Оценка текущего состояния выполняется на основании баланса
периода и финансовой подушки.

------------------------------------------------------------------------

## Основной принцип

Вкладка «Мои средства» ведётся независимо от текущего бюджета.

Изменения в этом разделе не создают автоматически доходы или расходы.

Аналогично, финансовые операции не изменяют остатки по счетам
автоматически.

Пользователь самостоятельно отражает изменения своих активов.

------------------------------------------------------------------------

## Виды средств

В первой версии приложения поддерживаются следующие виды активов:

-   банковские счета;
-   банковские карты;
-   вклады;
-   наличные;
-   пользовательские счета.

В дальнейшем список может быть расширен без изменения архитектуры
приложения.

------------------------------------------------------------------------

## Назначение средства

Для каждого средства указывается обязательное **назначение средства**.

Поддерживаются варианты:

-   **Текущие средства** --- средства, предназначенные для повседневного
    финансового оборота;
-   **Финансовые запасы** --- средства, которые не участвуют в
    постоянном повседневном обороте.

Тип средства (карта, счёт, вклад, наличные и т. д.) остаётся отдельным
полем и не определяет назначение автоматически.

------------------------------------------------------------------------

## Карточка счёта

Для каждого счёта указываются:

-   название;
-   тип;
-   назначение средства;
-   текущий остаток;
-   комментарий (необязательно).

При необходимости пользователь может добавить собственное описание.

------------------------------------------------------------------------

## Создание счёта

Пользователь может:

-   создать новый счёт;
-   изменить существующий;
-   удалить счёт;
-   временно скрыть счёт из общего списка.

Удаление счёта не удаляет ранее сохранённые снимки капитала.

------------------------------------------------------------------------

## Ежемесячный снимок

Для анализа изменений используется механизм ежемесячных снимков.

В настройках пользователь выбирает дату, когда фиксируется состояние
всех средств.

Каждый снимок сохраняет:

-   дату;
-   остаток по каждому счёту;
-   общую сумму средств.

Снимки не изменяются после сохранения.

------------------------------------------------------------------------

## История изменений

На основании ежемесячных снимков приложение отображает:

-   изменение общих средств;
-   изменение каждого счёта;
-   абсолютную разницу;
-   изменение в процентах.

История позволяет отслеживать долгосрочную динамику капитала.

------------------------------------------------------------------------

## Работа со вкладами

Для вкладов учитываются:

-   текущий остаток;
-   капитализация процентов;
-   изменение суммы вклада.

Если проценты капитализируются, они увеличивают только сумму вклада и не
считаются доходом текущего бюджета.

Если проценты перечислены на доступный счёт, приложение предлагает
добавить их в доходы текущего периода.

------------------------------------------------------------------------

## Расчёт сумм по назначению

Приложение автоматически рассчитывает:

-   текущие средства;
-   финансовые запасы;
-   общие средства.

Формулы приведены в разделе «Финансовые показатели и формулы».

------------------------------------------------------------------------

## Общие средства

Приложение автоматически рассчитывает:

> **Общие средства = Текущие средства + Финансовые запасы**

Этот показатель используется:

-   при отображении общей финансовой картины;
-   при отображении показателя «Мои средства» на главном экране;
-   при формировании финансовых наблюдений и аналитики.

Общие средства не используются для оценки текущего финансового
состояния бюджета.

------------------------------------------------------------------------

## Отображение информации

Для каждого счёта отображаются:

-   название;
-   тип;
-   текущий остаток;
-   изменение относительно предыдущего снимка (при наличии).

Для раздела в целом отображаются:

-   текущие средства;
-   финансовые запасы;
-   общие средства;
-   изменение за выбранный период;
-   процент изменения.

------------------------------------------------------------------------

## Финансовые наблюдения

На основании данных раздела приложение может формировать финансовые
наблюдения.

Например:

-   общий объём средств увеличился;
-   капитал снизился по сравнению с предыдущим месяцем;
-   наиболее заметные изменения произошли на определённых счетах.

Финансовые наблюдения имеют исключительно информационный характер.

------------------------------------------------------------------------

## Аналитика

На основании данных раздела в разделе «Отчёты и аналитика» может
формироваться подробный анализ за выбранный период.

Аналитика имеет исключительно информационный характер.

------------------------------------------------------------------------

## Будущие возможности

Архитектура должна предусматривать возможность добавления:

-   инвестиционных счетов;
-   ценных бумаг;
-   криптовалют;
-   драгоценных металлов;
-   валютных счетов;
-   автоматической загрузки остатков из банков.

------------------------------------------------------------------------

## Принципы раздела

Раздел «Мои средства» должен обеспечивать:

-   полное представление о финансовых активах пользователя;
-   независимость от текущего бюджета;
-   сохранение истории изменения капитала;
-   корректный учёт вкладов и капитализации процентов;
-   возможность дальнейшего масштабирования без изменения основной
    архитектуры приложения.

# 15. Отчёты и аналитика

## Назначение

Раздел «Отчёты и аналитика» предназначен для анализа финансового
состояния пользователя за выбранный период.

Раздел помогает увидеть структуру доходов и расходов, оценить изменения
бюджета и выявить финансовые тенденции.

------------------------------------------------------------------------

## Основной принцип

Все отчёты строятся автоматически на основании фактически подтверждённых
операций.

Плановые расходы и ожидаемые доходы до подтверждения в расчётах не
участвуют.

------------------------------------------------------------------------

## Доступные периоды

Пользователь может сформировать отчёт за:

-   неделю;
-   месяц;
-   год;
-   произвольный период.

Началом расчётов считается дата начала финансового периода,
установленная в настройках приложения.

------------------------------------------------------------------------

## Основные показатели

В каждом отчёте отображаются:

-   доходы периода;
-   расходы периода;
-   баланс периода (финансовый результат периода);
-   финансовая подушка (на дату формирования отчёта);
-   изменение общих средств (при наличии данных).

------------------------------------------------------------------------

## Отчёт по доходам

Отображается:

-   общая сумма доходов;
-   распределение по видам доходов;
-   доля каждого вида доходов;
-   динамика доходов относительно предыдущего периода.

------------------------------------------------------------------------

## Отчёт по расходам

Отображается:

-   общая сумма расходов;
-   распределение по категориям;
-   распределение по статьям;
-   доля каждой категории;
-   доля каждой статьи;
-   изменение расходов относительно предыдущего периода.

------------------------------------------------------------------------

## Отчёт по лимитам

Для каждого лимита отображаются:

-   установленная сумма;
-   фактические расходы;
-   остаток лимита;
-   процент использования;
-   наличие перерасхода.

------------------------------------------------------------------------

## Отчёт по средствам

На основании вкладки «Мои средства» отображаются:

-   общая сумма активов;
-   изменение капитала;
-   изменение по каждому счёту;
-   изменение в абсолютных значениях;
-   изменение в процентах.

------------------------------------------------------------------------

## Финансовая аналитика

Приложение автоматически формирует информационные наблюдения.

Например:

-   расходы по определённой категории увеличились;
-   лимит регулярно превышается;
-   баланс периода ниже финансовой подушки;
-   общая сумма активов выросла;
-   структура расходов изменилась.

Все наблюдения носят исключительно информационный характер.

------------------------------------------------------------------------

## Принципы аналитики

Аналитика должна быть:

-   объективной;
-   понятной;
-   спокойной;
-   без оценочных суждений;
-   без гендерных обращений.

Приложение не критикует пользователя и не навязывает решения.

------------------------------------------------------------------------

## Визуализация

В отчётах могут использоваться:

-   круговые диаграммы;
-   столбчатые диаграммы;
-   линейные графики;
-   сравнительные таблицы.

Визуальные элементы дополняют информацию, но не заменяют числовые
показатели.

------------------------------------------------------------------------

## Экспорт

Архитектура приложения должна предусматривать возможность экспорта
отчётов в:

-   PDF;
-   Excel;
-   CSV.

В первой версии функция экспорта может отсутствовать.

------------------------------------------------------------------------

## Будущие возможности

В дальнейшем могут быть добавлены:

-   сравнение нескольких периодов одновременно;
-   прогноз расходов;
-   прогноз доходов;
-   прогноз достижения финансовых целей;
-   пользовательские отчёты;
-   настраиваемые панели показателей.

------------------------------------------------------------------------

## Принципы раздела

Система отчётов и аналитики должна:

-   автоматически обновляться после изменения данных;
-   использовать только подтверждённые финансовые операции;
-   предоставлять объективную информацию;
-   помогать принимать финансовые решения;
-   легко расширяться новыми видами отчётов без изменения существующей
    архитектуры.

# 16. Настройки

## Назначение

Раздел «Настройки» предназначен для управления параметрами работы
приложения.

Все изменения настроек применяются автоматически и используются при
последующих расчётах без изменения ранее сохранённых финансовых данных.

------------------------------------------------------------------------

## Основные настройки

В первой версии приложения пользователь может настроить:

-   дату начала финансового периода;
-   финансовую подушку;
-   тему оформления;
-   дату ежемесячного снимка средств;
-   пользовательские статьи расходов;
-   пользовательские фразы финансового настроения.

Архитектура должна позволять добавление новых настроек без изменения
существующей структуры приложения.

------------------------------------------------------------------------

## Дата начала финансового периода

Пользователь самостоятельно выбирает день месяца, с которого начинается
финансовый период.

На основании этой даты рассчитываются:

-   текущий месяц;
-   отчёты;
-   лимиты;
-   аналитика.

Изменение даты начала периода не изменяет существующие операции, а
только влияет на их группировку в расчётах.

------------------------------------------------------------------------

## Финансовая подушка

В настройках пользователь может:

-   выбрать способ расчёта;
-   установить фиксированную сумму;
-   задать процент от дохода;
-   временно отключить использование финансовой подушки.

После изменения автоматически пересчитываются показатели и связанные
элементы интерфейса, на которые влияют изменённые настройки, в том
числе финансовое настроение и предупреждения.

------------------------------------------------------------------------

## Тема оформления

Приложение поддерживает несколько тем оформления.

В первой версии доступны:

-   Светлая;
-   Тёмная;
-   Японская.

Выбранная тема применяется ко всему приложению и сохраняется между
сеансами работы.

------------------------------------------------------------------------

## Дата ежемесячного снимка

Пользователь выбирает день месяца, в который фиксируется состояние
раздела «Мои средства».

На основании этих снимков строится история изменения капитала.

Изменение даты влияет только на будущие снимки.

------------------------------------------------------------------------

## Пользовательские статьи расходов

Пользователь может:

-   создать новую статью;
-   изменить название собственной статьи;
-   удалить собственную статью.

Системные статьи, входящие в первую версию приложения, удалить нельзя.

------------------------------------------------------------------------

## Пользовательские фразы

Для финансового настроения пользователь может добавить собственные
фразы.

Поддерживаются четыре логические группы фраз:

-   положительное;
-   нейтральное;
-   предупреждение;
-   критическое.

На главном экране отображаются четыре состояния финансового настроения:
Стабильное, Допустимое, Требует внимания и Критическое. Одному состоянию
может соответствовать несколько групп фраз.

При отображении финансового настроения приложение случайным образом
выбирает одну из доступных системных или пользовательских фраз группы,
сопоставленной с текущим состоянием.

------------------------------------------------------------------------

## Хранение настроек

Все настройки сохраняются локально и автоматически восстанавливаются при
следующем запуске приложения.

В первой версии используется localStorage.

Архитектура должна предусматривать возможность переноса настроек в
облачное хранилище в будущих версиях.

------------------------------------------------------------------------

## Сброс настроек

Пользователь может восстановить настройки по умолчанию.

Сброс настроек:

-   не удаляет финансовые операции;
-   не удаляет шаблоны;
-   не удаляет историю средств;
-   не изменяет отчёты.

Сбрасываются только пользовательские параметры приложения.

------------------------------------------------------------------------

## Назначение

Раздел «Уведомления» предназначен для своевременного информирования
пользователя о событиях, требующих внимания.

Уведомления помогают контролировать финансовую ситуацию, не вмешиваясь в
принятие решений.

------------------------------------------------------------------------

## Основной принцип

Уведомления носят исключительно информационный характер.

Приложение:

-   напоминает;
-   информирует;
-   предупреждает.

Приложение никогда не выполняет финансовые операции автоматически и не
принимает решения за пользователя.

------------------------------------------------------------------------

## Виды уведомлений

В первой версии используются следующие виды уведомлений:

-   информационные;
-   напоминания;
-   предупреждения.

------------------------------------------------------------------------

## Информационные уведомления

Используются для сообщения о произошедших событиях.

Например:

-   доход успешно сохранён;
-   расход успешно сохранён;
-   шаблон создан;
-   настройки изменены.

------------------------------------------------------------------------

## Напоминания

Напоминания используются для подтверждения запланированных действий.

К ним относятся:

-   подтверждение планового расхода;
-   подтверждение ожидаемого дохода;
-   напоминание о ежемесячном снимке средств.

Напоминание не создаёт финансовую операцию автоматически.

------------------------------------------------------------------------

## Предупреждения

Предупреждения отображаются при наступлении определённых условий.

Например:

-   превышен лимит;
-   баланс периода ниже финансовой подушки;
-   баланс периода отрицательный;
-   приближается окончание лимита.

Предупреждение не ограничивает работу пользователя.

------------------------------------------------------------------------

## Финансовое настроение

Финансовое настроение --- самостоятельный постоянный информационный блок
главного экрана.

Оно является отображением текущего финансового состояния и основано
только на сравнении баланса периода с финансовой подушкой.

Текст выбирается случайным образом из соответствующей группы
пользовательских или системных фраз.

Финансовое настроение:

-   не является уведомлением;
-   не является аналитикой;
-   не является отдельным финансовым расчётом;
-   не заменяет баланс периода;
-   описывает текущее состояние только на основании фактических данных.

Состояния на главном экране: Стабильное; Допустимое; Требует внимания;
Критическое.

Текст выбирается из групп фраз: положительное, нейтральное,
предупреждение, критическое. Одному состоянию может соответствовать
несколько групп фраз.

------------------------------------------------------------------------

## Финансовые наблюдения

**Финансовые наблюдения** --- автоматически сформированные
информационные выводы на основании фактических данных пользователя.

Финансовые наблюдения:

-   формируются автоматически;
-   основаны только на фактических данных;
-   не являются предупреждениями;
-   не требуют обязательного действия;
-   показывают изменения и тенденции.

Различие понятий:

-   **Финансовое настроение** --- текущее общее состояние;
-   **Уведомление** --- событие, напоминание или предупреждение;
-   **Финансовое наблюдение** --- информационный вывод по данным;
-   **Аналитика** --- подробный анализ за выбранный период.

------------------------------------------------------------------------

Каждое уведомление должно:

-   быть кратким;
-   содержать понятную причину;
-   при необходимости предлагать возможное действие;
-   не использовать обвинительные формулировки;
-   не содержать гендерных обращений.

3.  Информационные сообщения.

события.

## Назначение

Раздел «Работа с датами» определяет единые правила использования дат во
всех модулях приложения.

Единый подход обеспечивает корректность расчётов, отчётов, планирования
и аналитики.

Изменение даты автоматически влияет на все связанные расчёты.

-   не более 30 дней назад;
-   не более 60 дней вперёд.

приложения.

## Редактирование даты

## Финансовый период

Финансовый период определяется пользователем в настройках.

Началом периода считается выбранный день месяца.

Все операции автоматически относятся к соответствующему финансовому
периоду.

Изменение даты начала периода не изменяет сами операции, а только влияет
на их распределение в отчётах и аналитике.

------------------------------------------------------------------------

## Плановые расходы

Для плановых расходов используются две даты:

-   дата следующего выполнения;
-   дата фактического подтверждения.

До подтверждения расход не считается совершённым.

После подтверждения операция получает дату фактического создания либо
дату, указанную пользователем при подтверждении.

------------------------------------------------------------------------

## Ожидаемые доходы

Для ожидаемых доходов также используются две даты:

-   предполагаемая дата поступления;
-   дата подтверждения получения.

До подтверждения доход не участвует в расчётах.

После подтверждения операция получает дату фактического поступления либо
дату, указанную пользователем.

------------------------------------------------------------------------

снимка.

Она задаётся в настройках приложения.

Снимок фиксирует состояние средств на выбранную дату и сохраняется без
последующего изменения.

    восстановления.

## Основные принципы

Код должен быть:

-   простым;
-   читаемым;
-   логичным;
-   предсказуемым;
-   легко расширяемым.

## Архитектура

Код должен строиться по модульному принципу.

Каждый модуль отвечает только за свою область ответственности.

Модули взаимодействуют между собой через заранее определённые структуры
данных и интерфейсы.

## Разделение ответственности

В проекте должны быть разделены:

-   пользовательский интерфейс;
-   бизнес-логика;
-   работа с данными;
-   хранение данных.

Изменение интерфейса не должно требовать изменения бизнес-логики.

Замена способа хранения данных не должна влиять на остальной код
приложения.

## Повторное использование кода

Одинаковая логика должна быть реализована только один раз.

Повторяющийся код необходимо выносить в отдельные функции или модули.

## Именование

Названия переменных, функций и файлов должны:

-   отражать своё назначение;
-   быть понятными без дополнительных комментариев;
-   использовать единый стиль именования во всём проекте.

Следует избегать сокращений, если они ухудшают читаемость.

Комментарии используются только там, где код невозможно сделать

пересказывать очевидные действия программы.

## Обработка ошибок

Приложение должно корректно обрабатывать возможные ошибки.

При возникновении ошибки необходимо:

-   предотвратить потерю данных;
-   сохранить работоспособность приложения, если это возможно;
-   показать пользователю понятное сообщение без технических деталей.

Техническая информация должна использоваться только для разработки и
отладки.

------------------------------------------------------------------------

## Проверка данных

Все пользовательские данные должны проходить проверку перед сохранением.

Проверяются:

-   обязательные поля;
-   корректность форматов;
-   допустимые диапазоны значений;
-   логическая согласованность данных.

Некорректные данные не должны сохраняться.

и JavaScript без обязательной зависимости от сторонних библиотек.

Каждая функция должна выполнять одну понятную задачу.

было проверить независимо от пользовательского интерфейса.

Настоящий словарь определяет единое значение терминов, используемых в

## Операция

Финансовое событие, отражающее поступление или расход денежных средств.

Операция создаётся только после подтверждения пользователем.

------------------------------------------------------------------------

## Доход

Операция, увеличивающая текущий бюджет.

Доход участвует в расчётах бюджета, отчётах и аналитике после
подтверждения пользователем.

------------------------------------------------------------------------

## Расход

Операция, уменьшающая текущий бюджет.

Расход участвует в расчётах бюджета, лимитов, отчётов и аналитики после
подтверждения пользователем.

------------------------------------------------------------------------

## Вид дохода

Классификация доходов по источнику поступления.

В первой версии используются:

-   Постоянный;
-   Разовый;
-   Капитализация вклада.

------------------------------------------------------------------------

## Категория

Крупная группа расходов.

Используется для общего анализа структуры расходов и установки лимитов.

В первой версии предусмотрены категории:

-   Обязательные;
-   Для души.

------------------------------------------------------------------------

## Статья

Более детальная классификация расходов внутри категорий.

Одна и та же статья может использоваться в разных категориях.

Лимиты по статье рассчитываются независимо от категорий.

------------------------------------------------------------------------

## Лимит

Максимальная сумма расходов, установленная пользователем для категории
или статьи.

Лимит используется для контроля бюджета и не ограничивает возможность
добавления новых расходов.

------------------------------------------------------------------------

## Финансовый период

Период, за который рассчитываются показатели бюджета.

Дата начала финансового периода определяется пользователем в настройках
приложения.

------------------------------------------------------------------------

## Плановый расход

Запланированная расходная операция, ожидающая подтверждения
пользователем.

До подтверждения не участвует в расчётах бюджета.

------------------------------------------------------------------------

## Ожидаемый доход

Запланированное поступление денежных средств, ожидающее подтверждения
пользователем.

До подтверждения не учитывается в доходах и не влияет на бюджет.

------------------------------------------------------------------------

## Шаблон

Сохранённый набор параметров операции, предназначенный для быстрого
создания новой операции.

Шаблон не является финансовой операцией и не участвует в расчётах.

------------------------------------------------------------------------

## Финансовая подушка

Минимальный безопасный уровень средств, установленный пользователем.

Размер подушки может задаваться:

-   фиксированной суммой;
-   процентом от дохода.

Финансовая подушка не является суммой, которую нужно вычесть из средств.
Она используется как граница безопасности и не входит в расчёт баланса
периода.

------------------------------------------------------------------------

## Баланс периода

Результат подтверждённых операций выбранного финансового периода и
основной показатель оценки текущего финансового состояния.

> **Баланс периода = Доходы подтверждённых операций выбранного периода −
> Расходы подтверждённых операций выбранного периода**

Баланс периода не зависит от раздела «Мои средства» и не включает
финансовую подушку в свой расчёт.

------------------------------------------------------------------------

## Текущие средства

Сумма активных средств с назначением «Текущие средства».

Средства, предназначенные для повседневного финансового оборота.

------------------------------------------------------------------------

## Финансовые запасы

Сумма активных средств с назначением «Финансовые запасы».

Средства, которые не участвуют в постоянном повседневном обороте.

------------------------------------------------------------------------

## Общие средства

> **Общие средства = Текущие средства + Финансовые запасы**

Сумма всех активных средств пользователя с учётом их назначения.

Показывает объём активов пользователя и не используется для оценки
текущего финансового состояния бюджета.

------------------------------------------------------------------------

## Мои средства

Раздел приложения, предназначенный для учёта всех денежных активов
пользователя.

На главном экране показатель «Мои средства» отображает объём активных
денежных средств пользователя (общие средства).

Данные этого раздела ведутся независимо от текущего бюджета и не
используются для оценки текущего финансового состояния.

------------------------------------------------------------------------

## Счёт

Любое место хранения денежных средств в разделе «Мои средства».

Для каждого счёта указываются тип, назначение средства и текущий
остаток.

Например:

-   банковская карта;
-   банковский счёт;
-   вклад;
-   наличные;
-   пользовательский счёт.

------------------------------------------------------------------------

## Назначение средства

Обязательный признак каждого средства в разделе «Мои средства».

Варианты:

-   **Текущие средства** --- для повседневного финансового оборота;
-   **Финансовые запасы** --- не участвуют в постоянном повседневном
    обороте.

------------------------------------------------------------------------

## Ежемесячный снимок

Зафиксированное состояние раздела «Мои средства» на выбранную дату.

Используется для анализа изменения капитала.

------------------------------------------------------------------------

## Финансовое настроение

Самостоятельный постоянный информационный блок главного экрана
приложения.

Является отображением текущего финансового состояния на основании
сравнения баланса периода и финансовой подушки.

Не является отдельным финансовым расчётом, не является уведомлением и не
заменяет баланс периода.

Состояния на главном экране: Стабильное; Допустимое; Требует внимания;
Критическое.

Группы фраз для отображения: положительное, нейтральное, предупреждение,
критическое. Одному состоянию может соответствовать несколько групп фраз.

------------------------------------------------------------------------

## Финансовые наблюдения

Автоматически сформированные информационные выводы на основании
фактических финансовых данных пользователя.

Не являются предупреждениями и не требуют обязательного действия.

------------------------------------------------------------------------

## Аналитика

Подробный анализ финансового состояния пользователя за выбранный период
на основании подтверждённых операций и данных раздела «Мои средства».

Аналитика носит исключительно рекомендательный характер и не содержит
оценочных суждений.

Отличается от финансового настроения и финансовых наблюдений более
глубоким и периодным характером анализа.

------------------------------------------------------------------------

Информационное сообщение приложения.

Может содержать:

-   напоминание;
-   предупреждение;
-   подтверждение успешного действия;
